## Содержание лекции

### Путь запроса

Мобильное приложение или сайт только показывает данные. Считает и хранит их
сервис на сервере — **backend**. Путь запроса: кнопка в приложении → запрос
по адресу API → проверка данных → бизнес-логика → база данных → ответ.

| Часть | Что делает |
|---|---|
| API | набор адресов, по которым к сервису обращаются программы; для каждого известно, что он принимает и что вернёт |
| JSON | формат данных запроса и ответа |
| бизнес-логика | правила предметной области: что можно, что нельзя, как считать |
| база данных | таблицы, строки и связи между ними |

Программа работает только вместе с окружением: версией Python, библиотеками,
настройками. Поэтому сервис проверяют на чужом компьютере после чистого
клонирования.

### Контракт

**Контракт** — описание API, на которое опираются другие команды. Когда
формат согласован, команды приложения и сервиса работают параллельно.
Одно переименованное поле ломает приложение: оно показывает пустой экран.
Замороженный контракт меняется только по согласованию: добавлять поля можно,
удалять — нет.

### Сервис за год

Курс — один сквозной сервис, который растёт от темы к теме:

| Часть | Технологии |
|---|---|
| API | FastAPI, Pydantic, OpenAPI |
| база данных | PostgreSQL, SQLAlchemy, миграции Alembic |
| вход и права | пароли, JWT access и refresh, роли |
| кэш и фоновая задача | Redis, Celery |
| стенд и проверки | Docker Compose, GitHub Actions |
| логи и здоровье | структурированные логи, correlation ID, health и readiness |

Работа над каждой темой: планирование → реализация → проверки и Pull Request
→ демонстрация и разбор. Раз в несколько занятий сценарий ломается
намеренно: нужно найти причину, исправить минимальной правкой и показать,
что исправлено.

## Термины

| Термин | Значение |
|---|---|
| backend | часть системы на сервере: принимает запросы, считает, обращается к базе и возвращает ответ |
| API | набор адресов, по которым к сервису обращаются программы |
| контракт | описание API, на которое опираются другие команды |
| вертикальный срез | функция целиком: от запроса и проверки данных до записи в базу и ответа |
| миграция | шаг изменения схемы базы, записанный в код; его можно применить и откатить |
| транзакция | группа изменений, которая применяется целиком или не применяется совсем |
| идемпотентность | повторный запуск операции не меняет результат |
| кэш, TTL | копия дорогого результата и время её жизни |
| health / readiness | адреса, по которым сервис сообщает, жив ли он и готов ли принимать запросы |
| correlation ID | идентификатор запроса, который попадает в каждую запись лога |
| clean clone | проверка: клонировать репозиторий в пустую папку и запустить без ручной настройки |
