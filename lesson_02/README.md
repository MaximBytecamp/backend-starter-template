# Занятие 2 · окружение, модули и пакеты

Работа по теме 2 «Структура проекта»: то, что разбиралось в книге занятия,
вы повторяете на своём маленьком проекте.

**Разобрали:** зачем нужно отдельное окружение и как `.venv` меняет поиск
пакетов, выбор интерпретатора в VS Code, `pip` и PyPI на примере Rich, модуль
как файл с одной обязанностью, `import` и `__name__`, пакет и `__init__.py`,
запуск через `python -m`, `requirements.txt`, `.gitignore` и тесты на unittest.

Книга темы:
https://algorthimization-course-vvodnoe.vercel.app/mdk0101-razrabotka-modulei/lessons/02-struktura-python-proekta/index.html

## Что лежит в папке

```
start/trip.py      заготовка: один файл, в нём данные, расчёты и вывод
homework_02.md     домашнее задание
```

Заготовка работает без внешних зависимостей. Запустите её из папки `start`
командой `python3 trip.py` (на Windows `py trip.py`): напечатается отчёт
на 10 записей, 7900 ₽ всего и 790.00 ₽ средняя трата. Если чисел нет,
вы запустились из другой папки.

## Суть работы

Взять этот один файл и довести его до состояния проекта, который соберётся
у другого человека:

- рабочая копия заготовки в своей папке, окружение `.venv` рядом с ней;
- Rich из PyPI как первая зависимость, зафиксированная в `requirements.txt`;
- код разложен по модулям и собран в пакет `app` с `services` и `utils`,
  запуск идёт через `python -m app.main`;
- два новых расчёта и тесты к ним;
- README, по которому проект поднимается с нуля на чужом компьютере.

Что именно считать и какие числа должны получиться — в `homework_02.md`.

Раскладка, к которой нужно прийти:

```
app/__init__.py
app/main.py                   точка входа: данные, вызовы расчётов, печать
app/services/calculator.py    только расчёты, ничего не печатает
app/utils/formatter.py        только оформление отчёта
tests/test_calculator.py      тесты расчётов
requirements.txt
README.md
```

Правило деления одно: у модуля одна обязанность, расчёты не печатают,
а возвращают значения.

`python -m app.main` печатает отчёт, а `python app/main.py` падает
с `ModuleNotFoundError` — так и должно быть: при прямом запуске файла корень
проекта не попадает в пути поиска. Разбор этого места в главе 2.5.

## Как забрать папку и как сдать

Папка `lesson_02` появилась в шаблоне после того, как вы завели свой
репозиторий. Проще всего забрать её кнопками: на GitHub в шаблоне
**Code → Download ZIP**, распаковать и положить папку `lesson_02` к себе
в проект.

Работа уходит в ветку `hw-02` и дальше через Pull Request в вашу `main`.
Всё это делается кнопками в VS Code: [ветки](../docs/git/README.md#5-ветки) ·
[коммиты](../docs/git/README.md#3-изменения-и-коммиты) ·
[публикация ветки и Pull Request](../docs/git/README.md#6-ветки-на-github-и-pull-request).
Кому удобнее командами — в конце разбора есть
[шпаргалка «кнопка ↔ команда»](../docs/git/README.md#шпаргалка-кнопка--команда).

В описании Pull Request коротко: какие модули получились и почему границы
прошли именно там.

## Команды, которые понадобятся

Это уже про Python, а не про git, и они здесь нужны:

| Шаг | macOS / Linux | Windows (PowerShell) |
|---|---|---|
| создать окружение | `python3 -m venv .venv` | `py -m venv .venv` |
| активировать | `source .venv/bin/activate` | `.venv\Scripts\activate` |
| поставить Rich | `pip install rich` | то же |
| зафиксировать зависимости | `pip freeze > requirements.txt` | то же |
| запустить | `python -m app.main` | то же |
| прогнать тесты | `python -m unittest discover -s tests -v` | то же |

Проверка окружения: в начале строки появилось `(.venv)`, а команда
`python -c "import sys; print(sys.executable)"` печатает путь внутри `.venv`.
Этот вывод понадобится для README, скопируйте его сразу.
