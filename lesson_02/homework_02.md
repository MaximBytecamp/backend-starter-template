# Домашнее задание № 2 · отчёт по поездке

**Занятие 2 — окружение, модули и пакеты, тема 2 «Структура проекта»**

Максим Николаевич не хочет задавать вам домашнее задание. Но очень хочет.

Работа небольшая: заготовка около пятидесяти строк. Проверяется не объём,
а то, соберётся ли ваш проект на другом компьютере и по каким границам
вы разложили код.

Если из книги темы вы уже сдавали Student Tools, эта работа кладётся рядом,
в ту же папку занятия: `lesson_02/student-tools/` и `lesson_02/trip-report/`.
Задача та же по устройству, но разбирать границы модулей вам придётся заново,
на других данных.

## С чего начинаете

`start/trip.py` — расходы в поездке одним файлом: список трат, два расчёта
и печать отчёта. Что должно получиться на выходе и какие команды понадобятся,
описано в `README.md` этой папки.

## 1. Собрать проект по теме 2

Окружение `.venv`, зависимость Rich, пакет `app` с `services` и `utils`,
запуск через `python -m app.main`, `requirements.txt`, `.gitignore`, тесты.
Отчёт выводите таблицей Rich, а не через `print` со скобками.

## 2. Дописать два расчёта

В `app/services/calculator.py`, рядом с уже готовыми `calculate_total`
и `calculate_average`:

| Функция | Что возвращает |
|---|---|
| `most_expensive_day(expenses)` | номер дня с самой большой суммой и саму сумму |
| `category_share(expenses, category)` | долю категории в общих тратах, в процентах |

На пустом списке обе функции вызывают `ValueError`. На той же ошибке падает
и `category_share`, если такой категории в данных нет.

Числа, которые должны получиться на данных из заготовки:

| Что | Значение |
|---|---|
| Всего потрачено | 7900 ₽ |
| Средняя трата | 790.00 ₽ |
| Самый дорогой день | день 2, 2700 ₽ |
| Доля категории «еда» | 24.87 % |
| Доля категории «жильё» | 68.35 % |

Если ваши числа другие, расчёт неверный: данные у всех одинаковые.

## 3. Тесты

Не меньше пяти тестов в `tests/test_calculator.py`, среди них обязательно:

- обычный расчёт для каждой из четырёх функций;
- пустой список и `ValueError` — хотя бы для двух функций;
- несуществующая категория и `ValueError`.

Запуск: `python -m unittest discover -s tests -v`. Проценты сравнивайте
через `assertAlmostEqual`, иначе тест развалится на округлении.

## 4. README проекта

В `lesson_02/trip-report/README.md` напишите:

- фамилию, группу и одно предложение о том, что делает программа;
- версию Python и **свой** вывод `python -c "import sys; print(sys.executable)"`;
- структуру папок и обязанность каждого модуля одной строкой;
- команды: создать окружение, активировать, поставить зависимости, запустить,
  прогнать тесты — для вашей операционной системы;
- ожидаемый результат запуска;
- своими словами: почему `.venv` не кладут в репозиторий.

## 5. Проверка на чистом месте

Скопируйте проект в отдельную папку без `.venv`, соберите окружение заново
из `requirements.txt` и запустите. Что получилось, допишите в README.
Это тот пункт, на котором работа чаще всего и разваливается.

## Как сдавать

| | |
|---|---|
| **Где** | Папка `lesson_02/trip-report/` в вашем репозитории: пакет `app`, `tests/`, `requirements.txt`, `README.md` |
| **Ветка и PR** | Ветка `hw-02`, затем Pull Request в свою `main`. В описании: какие модули получились и почему границы прошли именно там |
| **Срок** | До начала следующего занятия |
| **Проверяю** | Скачиваю папку к себе, создаю новое окружение по вашему README, запускаю и сверяю числа. Дальше тесты и разговор про границы модулей |
| **В Git не должно быть** | `.venv/`, `__pycache__/`, `.env` — за этим следит `.gitignore` |

## Критерии, 10 баллов

| Что проверяется | Баллы |
|---|---|
| Структура: пакет, `__init__.py`, запуск через `python -m` | 2 |
| Воспроизводимость: чистое окружение, `requirements.txt`, README с командами | 2 |
| Расчёты: четыре функции, верные числа, `ValueError` где положено | 2 |
| Тесты: не меньше пяти, все проходят | 2 |
| README и чистота репозитория | 2 |

## Про ИИ

Модель хорошо объясняет сообщение об ошибке, помогает переписать текст README
и подсказывает недостающие тесты. Решение о том, что считать обязанностью
модуля, принимаете вы, и объяснять границы на review тоже вам. Код, который
вы не можете объяснить, к сдаче не принимается.

## Если сдаёте на Go

Тема 2 идёт двумя ветками, и домашнее задание тоже. На Go это `go mod init`,
пакеты в `internal/`, `go run .`, зависимости в `go.mod` и `go.sum`, тесты
в файлах `_test.go` и `go test ./...`. Задача и числа те же самые.
