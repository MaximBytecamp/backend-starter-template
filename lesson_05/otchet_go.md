компилятор и `go vet` находят ошибки до запуска программы, и как проект

## 3. Проверка в терминале

### go build до исправления

```text
✏️ Вставьте вывод команды go build ./... с двумя ошибками.
```

![Терминал VS Code с выводом go build ./...](img/go-05-build-errors.png)

*На снимке: терминал с той же командой и тем же выводом, что в блоке выше.*

Разбор первой строки ошибки:

| Часть строки | Значение в моём выводе | Что означает |
|---|---|---|
| файл | ✏️ | ✏️ |
| строка | ✏️ | ✏️ |
| столбец | ✏️ | ✏️ |
| сообщение | ✏️ | ✏️ |

✏️ Одним предложением: что означает строка `# example.com/otchet-kafe/proba`
над ошибками.

### Исправление и повторная проверка

```go
✏️ Вставьте исправленные строки proba/main.go.
```

```text
✏️ Вставьте команду go build ./... && go vet ./... и то, что она напечатала.
```

✏️ Одним предложением: как по такому ответу понять, что ошибок нет.

### Три уровня проверки

Файл из главы 4.3, §4 — тот, что собирается, но содержит подозрительные места, —
проверен тремя программами:

```text
✏️ Вставьте вывод go vet ./proba.
```

```text
✏️ Вставьте вывод go run honnef.co/go/tools/cmd/staticcheck@latest ./proba.
```

| Строка файла | Что не так | go build | go vet | staticcheck |
|---|---|---|---|---|
| ✏️ | ✏️ | ✏️ | ✏️ | ✏️ |
| ✏️ | ✏️ | ✏️ | ✏️ | ✏️ |
| ✏️ | ✏️ | ✏️ | ✏️ | ✏️ |

В колонках программ ставьте `⚠`, если программа отметила строку, и `—`, если нет.

✏️ Одним предложением: почему компилятор эти места не отмечает.
