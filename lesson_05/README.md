# Порядок работы на паре

Ниже — то, что вы делаете руками от начала до конца. Команды для macOS и Linux;
на Windows вместо `python3` пишите `py`, вместо `source .venv/bin/activate` —
`.venv\Scripts\activate`.

## Шаг 0. Забрать новую папку из шаблона

Папка `lesson_05/` появилась в шаблоне курса после того, как вы завели свой
репозиторий. Заберите её к себе:

```bash
git remote add upstream https://github.com/MaximBytecamp/backend-starter-template.git
git fetch upstream
git checkout upstream/main -- lesson_05
```

`git remote add` нужен один раз, дальше хватит `git fetch upstream`.
Проверка: `ls lesson_05` показывает `stend`, `homework` и `homework_05.md`.

## Шаг 1. Ветка на занятие

```bash
git switch -c lesson-05
```

Всё, что делаем дальше, живёт в этой ветке. В `main` попадёт через Pull Request.

## Шаг 2. Рабочая папка и окружение

Копируем стенд в место, где будем резать код. Оригинал в `stend/` не трогаем —
к нему удобно возвращаться и сравнивать.

```bash
cp -r lesson_05/stend lesson_05/orders-service
cd lesson_05/orders-service
python3 -m venv .venv
source .venv/bin/activate
pip install ruff mypy pytest
```

Проверка: в строке приглашения появилось `(.venv)`.

## Шаг 3. Убедиться, что стенд ломается так, как надо

```bash
python orders.py
cd .. && python orders-service/orders.py && cd orders-service
```

Первая команда напечатает `всего к оплате: 15067.0`, вторая — `всего к оплате: 0`.
Если у вас так же — стенд собран правильно, и мы начинаем именно с этого места.

## Шаг 4. Разрезать на пакет

Создаём раскладку и переносим код по модулям. Файлы можно делать и мышкой
в редакторе — команды здесь для тех, кому так быстрее:

```bash
mkdir -p src/orders data tests docs
mv orders.json data/orders.json
touch src/orders/__init__.py src/orders/py.typed
# дальше создаём модули и переносим в них функции из orders.py
```

Границы придумываете вы. Правило одно: **у модуля должна быть одна причина
меняться**, и вы называете её в docstring первой строкой файла.

Когда весь код разъехался по модулям, исходный `orders.py` удаляем:

```bash
git rm --cached orders.py 2>/dev/null; rm orders.py
```

## Шаг 5. Сделать пакет устанавливаемым

Создайте `pyproject.toml` (разбираем на паре, образец на экране) и поставьте пакет:

```bash
pip install -e .
python -m orders data/orders.json
cd .. && python -m orders orders-service/data/orders.json && cd orders-service
```

Проверка: обе команды печатают одинаковый отчёт и `всего к оплате: 15067`.
Дробных чисел в столбце сумм быть не должно.

## Шаг 6. Сломать намеренно и починить

Заведите встречный импорт между двумя модулями, запустите, сохраните вывод:

```bash
python -m orders data/orders.json 2>&1 | tee docs/incident-05.md
```

Дальше разорвите цикл передачей данных и допишите в `docs/incident-05.md`,
какой обязанности не хватало модулю.

## Шаг 7. Проверки

```bash
ruff check .
mypy
pytest -q
```

Все три должны молчать или сообщать об успехе. Одну ошибку, которую нашёл
mypy по дороге, разберите письменно — это отдельный пункт приёмки.

## Шаг 8. Карта импортов

`docs/import-map.md` — таблица «модуль → причина меняться → кого импортирует».
Стрелок снизу вверх быть не должно.

## Шаг 9. Сдать

```bash
cd ../..
git add lesson_05
git commit -m "lesson-05: сервис заказов разрезан на пакет"
git push -u origin lesson-05
```

Дальше на GitHub открываете **Pull Request** в свою `main`. В описании:
было файлов → стало модулей, сколько имён наружу, где был цикл и как убрали.

Всё то же самое можно делать мышкой в VS Code, без терминала. Разбор
со скриншотами: [коротко](../docs/git/README.md), [подробно](../docs/git/FULL.md).
