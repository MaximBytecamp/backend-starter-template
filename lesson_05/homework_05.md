# Домашнее задание № 2

**Занятие 5 — структура пакета и типизированный публичный интерфейс**

Максим Николаевич не хочет задавать вам домашнее задание. Но очень хочет.

## Что нужно сделать

Заготовка лежит рядом: `homework/library.py` и `homework/loans.json`.
Порядок работы тот же, что на паре, — он расписан по шагам в `README.md`
этой папки. Здесь только то, что отличается.

### 1. Разрежьте `library.py` на пакет

Выдача книг: читатели, экземпляры, выдача, возврат, штраф за просрочку,
отчёт по должникам. Разложите функции по модулям так, чтобы у каждого была
**одна причина меняться**, и назовите эту причину первой строкой файла
в docstring. Минимум пять модулей плюс `__init__.py`.

Подсказка по причинам: «изменилась цена штрафа», «изменились лимиты по ролям»,
«переехали с JSON на базу», «поменялся вид отчёта» — это разные причины,
значит, и разные файлы.

### 2. Сделайте проект устанавливаемым

- `src`-layout: пакет лежит в `src/library/`;
- `pyproject.toml` с `packages = ["src/library"]` и настройками Ruff и mypy;
- пустой файл `py.typed` внутри пакета;
- `pip install -e .`.

Проверка: `python -m library data/loans.json` печатает одинаковый отчёт
из папки проекта и из папки уровнем выше.

### 3. Типизируйте публичные функции

Аргументы и возвращаемое значение у всего, что попало в `__all__`.
Имена типов вынесите в отдельный модуль: идентификатор выдачи, номер
читательского билета, деньги, роль. Прогоните `mypy` и **разберите письменно
одну найденную ошибку**: что проверка увидела и почему это действительно ошибка.

В заготовке такая ошибка есть — ищите там, где целое число превращается в дробное.

### 4. Сломайте намеренно и почините

Заведите встречный импорт между двумя модулями, запустите, сохраните
трассировку в `docs/incident-05.md`. Рядом напишите:

- какой обязанности не хватало модулю;
- почему передача данных параметром решает задачу лучше, чем импорт внутри функции.

### 5. Нарисуйте карту импортов

`docs/import-map.md`: таблица «модуль → причина меняться → кого импортирует».
Стрелок снизу вверх быть не должно. Отдельной строкой ответьте: **что придётся
открыть, если библиотека переедет с JSON на PostgreSQL.**

| **ИИ** | Сначала режете сами. Модель хорошо разбирает сообщение об ошибке и предлагает недостающие тесты — и плохо решает, где провести границу, потому что причин меняться она не знает. Границы придумываете вы, объяснять их на review тоже вам |

Объём кода небольшой: заготовка — около ста строк, как и `orders.py` на паре.
Задание не про количество написанного, а про то, где вы проведёте границы
и сможете ли объяснить их на review.

## Словарь занятия

| Термин | Что значит |
|---|---|
| Модуль | Один файл `.py` и всё, что в нём объявлено. При импорте выполняется сверху вниз |
| Пакет | Папка с `__init__.py`: даёт файлам внутри общее имя и служит дверью наружу |
| `src`-layout | Раскладка, при которой пакет лежит в `src/` и виден только после установки |
| Публичный интерфейс | Имена в `__all__`: то, чем пользуются снаружи и что нельзя переименовать молча |
| Аннотация типа | Запись ожидаемого типа аргумента и результата; проверяет её mypy, а не интерпретатор |
| Псевдоним типа | Своё имя для существующего типа: `type Money = int`. Проверку не усиливает, смысл объясняет |
| Циклический импорт | Два модуля импортируют друг друга; падает с `partially initialized module` |
| `py.typed` | Пустой файл внутри пакета: заявляет, что пакет типизирован |
